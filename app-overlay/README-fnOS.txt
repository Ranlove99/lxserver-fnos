洛雪音乐（LX Music Web + 同步服务）—— fnOS 版说明
==================================================

这是什么
------------
XCQ0607/lxserver 的飞牛打包版，两个能力合一：

1) 网页播放器：浏览器打开就能搜歌、播放、下载、管歌单，不用装客户端。
2) 数据同步服务：桌面端 / 手机端洛雪音乐把「我的列表、收藏、不喜欢」同步到 NAS。

内置 Node.js 22 运行时与音频指纹工具 fpcalc，安装后即可用，不需要联网装依赖。

访问方式
------------
· 网页播放器：点飞牛桌面图标，或应用中心点「打开」。
  走的是飞牛统一网关（/app/lxserver），与桌面同源，
  所以无论你用 http 还是 https 访问飞牛桌面都能正常打开。
· 也可以直连：  http://NAS地址:9527/
· 客户端同步：  http://NAS地址:9527/用户名     ← 例如 http://192.168.1.10:9527/admin

客户端里配置：洛雪音乐 → 设置 → 数据同步 → 启用，
  「同步服务地址」填上面第二个（必须带用户名，不能只填到端口）
  「用户名 / 密码」填安装向导里设置的那组
连接成功后显示的服务名就是向导里填的「服务名称」。
提示：单用户模式下如果安装时没填密码，系统会自动生成一个随机密码占位，
      网页端用不到它；但手机/电脑客户端要做数据同步时就必须要这组凭据，
      可在「后台管理 → 用户管理」里重置，或安装时直接填一个自定义密码。

常用位置
------------
配置文件：/var/apps/lxserver/var/data/config.js
          （改完到应用中心重启应用生效）
运行日志：/var/apps/lxserver/var/logs/ 与 /var/apps/lxserver/var/app.log
数据目录：/var/apps/lxserver/var/data/  （用户数据、歌单快照、缓存、封面）
端口记录：/var/apps/lxserver/etc/app.env

改端口
------------
编辑 etc/app.env 把 PORT=9527 改成新端口 → 应用中心重启。
桌面图标走网关，与端口无关，改端口不影响点图标打开；
直连访问则换成 http://NAS地址:新端口/ 。

关于用户模式与密码
------------
安装向导第一步可选用「单用户模式」（默认开启）或「多用户模式」：

· 单用户模式：不需要登录，打开即用。自定义源、本地音乐、服务器缓存、
  后台管理等原本要求管理员身份的功能全部直接可用，也无需额外密码。
· 多用户模式：需要账号 + 密码，网页播放器会显示登录入口，数据同步可用。

想从单用户改成多用户（或反向），重新安装一次并在向导里选择即可，
已有配置会被备份为 config.js.bak-时间戳，歌单/收藏等数据不受影响。

后台管理
------------
播放器左侧菜单（手机端在左上角菜单）里的「后台管理」即可进入，
也可以直接访问：
  网关方式：https://飞牛地址/app/lxserver/admin/
  直连方式：http://NAS地址:9527/admin/
单用户模式下直接进入，不需要输入密码。

已默认关闭的项
------------
· disableTelemetry 已设为 true：关闭项目的 PostHog 使用统计上报。
· 未配置 WebDAV 远端备份：需要的话在 config.js 里开 webdav.enable。

本地曲库
------------
播放器支持「本地音乐」。要让应用读到 NAS 上的音乐文件夹，
到 飞牛设置 → 应用 → 洛雪音乐 → 授权目录，把音乐目录授权给它，
然后在播放器里指定该目录。默认只读写自己的 var/data。

外网访问
------------
本服务不带 HTTPS，且项目有 IP 限流。要公网使用请用 Nginx 反代并加 TLS，
同时设置环境变量 PROXY_HEADER=x-real-ip（或在 config.js 里改 proxy.header），
否则所有请求会被识别成同一个 IP，容易被限流误封。

故障排查
------------
· 打开网页空白：
  - 先确认应用是「运行中」。
  - 本版走飞牛统一网关，页面与桌面同源，正常不会再出现「混合内容」白屏。
    若仍空白，直接访问 http://NAS地址:9527/ 验证服务本身是否正常：
    · 直连正常 → 说明是入口/网关问题，重启应用（会重建 app.sock）后重试；
      仍不行可执行 systemctl restart trim_app_center.service 刷新桌面入口。
    · 直连也空白 → 看 var/app.log 末尾的报错。
· 客户端连不上：地址必须带用户名；确认端口未被防火墙拦。
· 启动失败：看 var/app.log 末尾，常见是端口被占用（换端口）或数据目录权限。
· 换了架构的机器：本包装不上会直接提示架构不符，请用对应架构的安装包。
